# Formulae and casks installed with Homebrew. One per line; "#" a comment.
#
# Fully-qualified names (user/tap/formula) are fine -- "brew install" taps
# automatically, and since Homebrew 7 it also trusts the named formula, where
# an unqualified name from a third-party tap is refused. setup.sh matches
# against installed packages on the segment after the last "/", since
# "brew list" reports the short name.
#
# What belongs here rather than in apt.txt: tools that move faster than the
# Ubuntu release cycle, and tools Ubuntu does not package at all. The gap is
# not academic -- apt ships gh 2.46 against brew's 2.100.

# --- AI tooling -------------------------------------------------------------

# opencode V2. It is a separate formula from V1 ("opencode"), available only
# from the upstream tap -- homebrew-core has no opencode-v2 -- and it declares
# conflicts_with "opencode", since both ship a binary named opencode.
#
# setup.sh does not install this line the ordinary way. Where V1 is present,
# from brew or from the install script, it asks before replacing it, because
# V2 migrates the shared session database in place on first launch; it backs
# that database up, uninstalls V1, installs V2, and puts V1 back if V2 fails.
# With no terminal to ask on, V1 is kept unless --upgrade-opencode is passed.
# See ensure_opencode_v2 in lib/setup-lib.sh.
anomalyco/tap/opencode-v2

# CLI for talking to LLMs.
llm

# Agent memory. In homebrew-core; the install-script copy that ships to
# ~/.local/bin goes stale silently and shadows this one on PATH.
beads

# --- Development ------------------------------------------------------------

# apt has 2.46.0 against 2.100.0 here -- by far the worst lag of anything
# Ubuntu packages that we actually use.
gh

# apt 4.2.3 vs 4.4.3.
cmake

# apt 0.67.0 vs 0.74.3.
fzf

# Same version as apt today, but brew tracks new releases and apt will not
# until the next Ubuntu.
shellcheck

# node and pnpm are deliberately NOT here; see ubuntu26/brew.txt. Machines
# running a toolchain manager get them from it instead, and having both
# supply the same binary is what let a project pinned to pnpm 10 run pnpm 11.

# Not packaged by Ubuntu at all. The install script drops it in ~/.local/bin
# where it goes stale unnoticed.
uv
